## TLS

clienthello-serverhello-clientkeyexchange-changecipherspc  
通常经过「四个消息」就可以完成 TLS 握手，也就是需要 2个 RTT 的时延.  
HTTPS 是应用层协议，需要先完成 TCP 连接建立，然后走 TLS 握手过程后，才能建立通信安全的连接。

传统的 TLS 握手基本都是使用 RSA 算法来实现密钥交换的
### RSA

客户端上传随机密钥，用服务端公钥加密。
![rsa](/images/https_rsa.webp)

CA签发流程：
1. 服务端生成密钥对：私钥自己保管，公钥放进 CSR（证书签名请求）。
2. 服务端把 CSR 发给 CA：CSR 里包含公钥和域名等信息，但不含私钥。
3. CA 验证身份/域名控制权：确认申请者确实控制该域名。
4. CA 用自己的私钥对证书内容签名：签名的对象是“证书里的一堆信息”，包括服务端公钥、域名、有效期、颁发者等。不是“给公钥加密”，而是对证书内容做数字签名。
5. 客户端验证证书：客户端用 CA 的公钥验证 CA 的签名，确认这张证书确实是该 CA 签发的、内容没被篡改；然后从证书里取出服务端公钥。

TLS 握手中服务端用私钥签名：客户端用证书里的服务端公钥验证，确认对方持有对应私钥。

第一次握手：  
消息里面有客户端使用的 TLS 版本号、支持的密码套件列表，以及生成的随机数（Client Random），这个随机数会被服务端保留，它是生成对称加密密钥的材料之一。
第二次握手：  
当服务端收到客户端的「Client Hello」消息后，会确认 TLS 版本号是否支持，和从密码套件列表中选择一个密码套件，以及生成随机数（Server Random）。返回「Server Hello」消息

此时就有了两个随机数

密码套件：密钥交换算法 + 签名算法 + 对称加密算法 + 摘要算法  
一般 WITH 单词前面有两个单词，第一个单词是约定密钥交换的算法，第二个单词是约定证书的验证算法。  
服务端为了证明自己的身份，会发送「Server Certificate」给客户端，这个消息里含有数字证书。
随后，服务端发了「Server Hello Done」消息。

一个数字证书通常包含了：
- 公钥；
- 持有者信息；
- 证书认证机构（CA）的信息；
- CA 对这份文件的数字签名及使用的算法；
- 证书有效期；
- 一些其他额外信息；

![证书](/images/证书的校验.webp)

第三次握手：

验证完成证书后，生成新随机数用服务器的RSA公钥加密。

至此，客户端和服务端双方都共享了三个随机数，分别是 Client Random、Server Random、pre-master

客户端再发一个「Encrypted Handshake Message（Finishd）」消息，把之前所有发送的数据做个摘要

第四次握手：

服务器也是同样的操作，发「Change Cipher Spec」和「Encrypted Handshake Message」消息，如果双方都验证加密和解密没问题，那么握手正式完成。

但是现在大多数网站使用的正是 ECDHE 密钥协商算法

### ECDHE 

ECDHE 密钥协商算法是 DH 算法演进过来的，该算法的核心数学思想是离散对数

## 基础概念

### 1. OSI 七层模型分别是什么？

从下到上依次是物理层、数据链路层、网络层、传输层、会话层、表示层和应用层。TCP/IP 模型通常分为网络接口层、网际层、传输层和应用层。

### 2. TCP 和 UDP 有什么区别？

TCP 面向连接，提供可靠、有序的字节流传输，并支持流量控制和拥塞控制。UDP 无连接，传输开销较小，但不保证数据可靠到达或按序到达。网页传输常使用 TCP，实时音视频等场景常使用 UDP。

### 3. TCP 三次握手的过程是什么？

客户端发送 SYN；服务端回复 SYN+ACK；客户端再发送 ACK。通过三次交互，双方确认彼此的收发能力并同步初始序列号。

### 4. TCP 四次挥手的过程是什么？

一方发送 FIN，另一方回复 ACK；另一方准备好关闭时发送 FIN，最初一方再回复 ACK。由于 TCP 的发送和接收方向可以独立关闭，通常需要四次交互。

### 5. TCP 如何实现可靠传输？

TCP 使用序列号和确认应答识别数据，利用超时重传应对丢包，并通过校验和检测数据错误；滑动窗口则用于协调发送与接收速度。

### 6. 流量控制和拥塞控制有什么区别？

流量控制避免发送方发送速度超过接收方的处理能力；拥塞控制则根据网络状况调整发送速度，避免网络整体过载。

### 7. IP 地址和 MAC 地址有什么区别？

IP 地址用于网络层寻址，支持跨网络转发；MAC 地址用于数据链路层，在本地链路上标识网络接口。数据经过路由器时，链路层帧中的 MAC 地址会改变。

## 常见协议

### 8. DNS 的作用是什么？

DNS 负责将域名解析为 IP 地址。解析结果可以被浏览器、操作系统或 DNS 解析器缓存，以减少重复查询。

### 9. HTTP 和 HTTPS 有什么区别？

HTTPS 是使用 TLS 保护的 HTTP。TLS 可提供通信加密、完整性校验和服务器身份验证；普通 HTTP 不提供这些保护。

### 10. 常见 HTTP 状态码有哪些？

- `200`：请求成功。
- `301`、`302`：资源重定向。
- `400`：请求有误。
- `401`、`403`：未通过身份验证或无权访问。
- `404`：资源不存在。
- `500`：服务器内部错误。

### 11. GET 和 POST 有什么区别？

GET 通常用于获取资源，参数常放在 URL 中；POST 通常用于提交数据，数据常放在请求体中。是否幂等取决于接口语义，不能仅凭方法名称判断。

### 12. 输入网址后，页面大致如何显示出来？

浏览器解析 URL，通过 DNS 查询服务器 IP，建立 TCP 连接（HTTPS 还需进行 TLS 握手），发送 HTTP 请求并接收响应，最后解析页面资源并完成渲染。


## TLS 协议

TLS（Transport Layer Security，传输层安全协议）是用于在网络中提供安全通信的协议，主要用于保护 HTTP（即 HTTPS）、SMTP、IMAP 等应用层协议的数据传输安全。

### TLS 的主要功能

- **加密**：对传输的数据进行加密，防止被窃听。
- **身份认证**：通常通过证书验证服务器身份，防止中间人攻击。
- **数据完整性**：通过消息认证码（MAC）防止数据被篡改。

### TLS 握手过程简述
1. 客户端发起连接请求，发送支持的加密算法等信息。
2. 服务器返回证书和加密参数。
3. 客户端验证证书，生成会话密钥并加密发送给服务器。
4. 双方使用协商好的密钥进行加密通信。

### TLS 与 SSL 的关系
TLS 是 SSL 的升级版，SSL 已不再安全，实际应用中多使用 TLS。
